# Game Art Asset Creation

## 职责

把批准的美术设计转化为尺寸、格式、命名、版本、性能和导入规则明确的游戏资产。负责生产与交付，不擅自改变玩法碰撞、角色比例、状态识别或视觉支柱。

资产逻辑ID和用途来自`game-system-design`的资产需求表，视觉方案来自`game-art-design`；循环图不是资产生产清单。将导出文件映射回资产ID和行为反馈，不因素材缺失改变玩法状态或结算次数。

## 工作模式

按资产和阶段选择一种主模式；公共ID和交接见[插件级路由与交接契约](../../references/skill-routing-and-handoff.md)，正式记录读[资产生产模板](templates/asset-production-template.md)。

- **规格／排产**：定义清单、来源授权、技术规格、依赖、批次与验收，不声称已生产文件。
- **代表性生产**：先完成一项代表资产并做引擎验证，再决定批量规则。
- **批量生产／打包**：按已批准规格生产变体、导出、命名和版本包，不在批处理中改变视觉基线。
- **验证／修复**：检查已有资产的视觉、导入、动画、性能和授权问题，只修复用户授权范围。

## 工作流

1. 确认资产用途、目标引擎、镜头距离、屏幕占比、目标平台和批准的美术设计。
2. 在生产前建立资产规格：类型、尺寸、拓扑或像素密度、色彩空间、透明度、枢轴、坐标轴、单位、骨骼、动画、贴图通道、LOD、压缩和导出格式。
3. 确认来源和授权。区分原创、用户提供、生成式素材、第三方许可和占位资产。
4. 先制作代表性资产并完成引擎测试，再批量生产同类资产。
5. 保持确定性命名、稳定目录、源文件与导出文件分离、版本可追踪。
6. 在目标引擎中检查外观、比例、枢轴、碰撞配合、动画事件、材质、Mip、压缩和运行时成本。

## 专项路由

- 2D 帧动画、序列帧、Sprite Sheet、pivot、帧率和 Unity 导入：调用仓库中的 `2d-game-animation-assets`。
- AI 图像生成或编辑：使用当前环境的图像生成能力，并将输出标注为概念、源素材或候选成品。
- Unity Sprite、Atlas、导入和 UI：调用匹配的 Unity 专项技能。
- 3D 模型、绑定或动画：遵循项目 DCC、骨架、坐标和导出规范；没有对应工具时交付精确制作规范，不声称已经生成文件。

## 资产清单字段

每项资产记录：

- 唯一 ID、显示名和用途。
- 负责人、状态和来源授权。
- 源文件路径、导出路径和目标引擎路径。
- 技术规格和依赖。
- 版本、变体和重用关系。
- 视觉验收与技术验收。
- 已知问题和返工条件。

## 质量门槛

- 资产符合批准的视觉支柱和玩法可读性。
- 源文件、导出文件和引擎资产职责分离。
- 单位、比例、枢轴、方向和命名一致。
- 透明边缘、贴图通道、色彩空间和压缩设置正确。
- 动画循环、事件帧和根运动策略明确。
- 资产已在代表性场景和目标质量档位中检查。
