# 合成案例：开箱结算拆解

这是专为技能演示的虚构材料，不是《幸运房东》或其他发行游戏的逆向结果，也不是原“五步开箱”示例的正式改版。

## 给定原始材料

证据TXT-01，虚构UI：“金箱：消耗2钥匙，获得8金币。行动结束时检查目标。”

证据SRC-01，虚构源码摘录，构建demo-A：

```text
openGold:
  if ended or actions < 1 or keys < 2: return rejected
  keys -= 2
  coins += 8
  actions -= 1
  if coins >= 13: ended = true; result = won
  else if actions == 0: ended = true; result = lost
  emitSummary()
```

没有提供运行录像、完整注册表、存档或随机代码。

## 正确语义化

| 规则ID | 触发条件 | 作用目标 | 效果 | 数值 | 次数／范围 | 结算时点 | 失败／例外 | 证据状态 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| ACT-GOLD | 请求开金箱且未结束、行动≥1、钥匙≥2 | 本局玩家资源与局状态 | 扣钥匙，加金币，扣行动；再判胜负并发汇总通知 | -2钥匙、+8金币、-1行动；金币≥13胜 | 每个被接受请求一次；是否有重入防护未知 | 按所列顺序同步写入；胜利先于行动耗尽 | 前提不满足直接拒绝，不扣资源；通知不再发奖 | SRC-01静态片段支持；调用者和实际运行未核查 |

UI未写行动费用，不能因此认为无行动费用；这是说明遗漏，不是直接证明运行冲突。初始金币5、钥匙2、行动1时，按片段演算得到13金币、0钥匙、0行动且胜利；不能写成“行动归零先失败”，不能声称已在游戏验证。

## 交接与停止点

可以交接ACT-GOLD的局部行为与最后一步达标用例，正式树由系统设计维护。仍需确认入口是否重复调用、初始资源来源、全局目标覆盖、内容总量与存档提交；不能输出“全部宝箱系统已完整还原”，也不能因给定局部代码无随机而说整个游戏没有随机。
