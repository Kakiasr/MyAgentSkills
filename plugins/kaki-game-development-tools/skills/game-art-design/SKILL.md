# Game Art Design

## 职责

把玩法、世界观、镜头与平台限制转化为一致且可生产的视觉方案。负责“应该长什么样、为什么这样设计、怎样保持一致”，不直接把概念图当作最终可用资产。

从`game-design`读取体验与动作反馈，从`game-system-design`读取状态、行为和资产需求，从`game-loop-design`读取反馈频率与节律。只定义视觉表达，不改写资源费用、触发条件或胜负；出现信息缺口回交对应设计技能，不另造第二套规则。

## 工作模式

按请求选择方向定义、专项简报或视觉评审，不默认同时重做全部美术。公共ID和交接见[插件级路由与交接契约](../../references/skill-routing-and-handoff.md)；正式交付读[美术设计模板](templates/art-direction-template.md)。

- **视觉方向**：建立全项目视觉支柱、形状、色彩、材质、镜头和可读性基线。
- **专项简报**：只处理角色、环境、UI、动画或VFX中的指定类别，并引用既有`VIS-*`基线。
- **视觉评审**：对照批准基线指出偏差、影响与修改优先级，不擅自替换设计方向。

## 工作流

1. 读取游戏设计目标，提取玩家情绪、信息优先级、镜头距离、交互频率和目标平台。
2. 建立视觉支柱：主题、时代与文化依据、形状语言、比例、轮廓、色彩、明度、材质、光照和动效特征。
3. 分别定义角色、场景、道具、UI、动画和 VFX 的视觉规则及共享约束。
4. 用 gameplay readability 检查敌我、可交互物、危险、奖励、路径和状态反馈是否清晰。
5. 形成可交给资产制作与技术美术的规格，而非只给情绪描述。
6. 需要概念图或视觉探索图时，使用可用的图像生成能力；生成结果标为概念参考，记录需要人工统一和修正之处。

## 美术设计简报

至少包含：

- 设计目标与不采用的方向。
- 3 至 5 个视觉支柱。
- 形状、比例、轮廓、色彩、明度和材质规则。
- 镜头与构图约束。
- 角色、环境、道具、UI、动画、VFX 分项规则。
- 关键状态和 gameplay 信息的视觉编码。
- 参考图用途说明：借鉴什么、不借鉴什么。
- 资产制作约束与技术美术问题清单。

## 质量门槛

- 风格必须服务于体验、可读性和生产规模。
- 关键玩法信息不能只依赖色相，需考虑明度、形状或动效冗余。
- 同类资产必须共享比例、透视、光照和材质规则。
- 参考图不能替代原创设计决策，也不能要求复制在世艺术家的独特风格。
- 所有概念提案都要能转化为资产规格和验收条件。
