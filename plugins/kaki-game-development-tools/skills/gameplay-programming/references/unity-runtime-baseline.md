# Unity运行时实现基线

本基线整理自用户提供的《Unity项目开发规范》，用于Unity玩法实现时的默认判断。它是可裁剪的项目基线，不是覆盖现有工程约定的绝对命令；冲突时保留现有架构，必要改变使用`DEC-*`记录。

## 角色与依赖

- Director／Facade：整局初始化、结束和跨系统协调，不拥有可独立变化的领域算法。
- Domain System：拥有一个领域的规则和运行时状态，对外提供意图命令和只读查询。
- Actor：拥有单个运行实体的局部状态、Transform、碰撞和表现引用，不拥有整局状态。
- Event Source：广播已经发生的事实，不保存玩法状态或引用订阅者。
- View／UI：显示状态并转发用户意图，不直接修改领域容器。
- Config／Definition：保存静态规则和定义，不保存本局状态。

命令要求结果、顺序或失败语义时使用方法；同步读取用查询；一对多通知用过去式事实事件。不要把所有通信都事件化。

## 生命周期

```text
Awake：缓存作者状态、解析本地引用，不开始整局
OnEnable：订阅；OnDisable/OnDestroy：对称解绑
StartRun：校验→重置→初始化→进入流程→发布开始事实→开放输入
Tick：高层状态→输入→模拟→规则结算→事实事件→轻量显示刷新
EndRun：停止模拟→固化结果→切换状态→发布结束事实→表现收尾
```

- `Reset`必须幂等，连续调用和连续重开不得残留实体、队列、计时器、库存、分数、暂停或UI状态。
- 同一系统由Director `Tick`或自身Unity消息驱动，不能两者同时存在。
- 物理输入采样与`FixedUpdate`解算分开。
- 玩法时间、固定步长和`unscaledDeltaTime`用途明确；`Time.timeScale`只有一个权威写入者。

## 状态、事件和运行数据

- 互斥状态使用枚举或显式状态对象，不使用多个可能冲突的布尔值。
- 状态机定义初态、守卫、合法转移、非法请求、进入／退出副作用以及Previous/Current事件。
- C#事件订阅不使用无法解除的匿名Lambda；订阅者不得反向修改事件源内部状态。
- 事件载荷优先不可变，避免携带可变内部集合、Director或事件源本身。
- 运行时生成内容来自显式Prefab、工厂或生成表；动态对象的回收／销毁必须清理订阅与引用。

## Unity代码约定

- 默认`sealed`仅适用于没有已知继承需求的具体组件；不要为了规范破坏现有扩展层次。
- 序列化字段默认`private`，公共面只暴露意图API与只读状态。
- Unity消息保持短小，复杂算法放入领域类或纯C#对象。
- 公共类型、接口和非显然生命周期／序列化约束使用中文XML注释；私有代码按复杂度注释，不做无信息重复。
