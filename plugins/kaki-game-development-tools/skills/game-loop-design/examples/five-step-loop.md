# 五步开箱：循环示例

规则基线见同插件[系统设计示例](../../game-system-design/examples/five-step-chests.md)。这是教学用原创设计草案，不是《幸运房东》的循环，也不是经过玩家测试的结论。

## 循环

- 小循环：查看钥匙、金币和行动→选择补给／开箱→验证并提交→收到资源反馈→重新规划。成功操作消耗1行动；失败请求不扣费。再次选择的原因是逐渐逼近13金币目标，而非自动获得永久成长。
- 单局循环：从1钥匙、0金币、5行动开始，反复执行小循环；先检查达标再检查行动耗尽，因此最后一步达标也是胜利。
- 重试循环：看结局→主动选择再玩→完全重置局内数据。保留的是玩家对路线的理解，不保留旧钥匙、金币或已开宝箱。也可返回标题退出本局。

## 画图

可编辑语义与布局输入：[five-step-loop.json](five-step-loop.json)。用本技能`scripts/render_loop.py`生成SVG和Mermaid到项目产物目录；不把生成结果写入插件源码。

图中只有行为、信息、分支三类节点；本例没有需要单独引用的子循环，不强制凑齐四类。循环体内单独标明当前钥匙、当前金币、剩余行动次数和13金币目标四项全局可获取信息，不串入步骤箭头。一次行动反馈与胜负结果作为流程信息节点。以下规则走读留在图外，不作为图中脚注。

## 规则走读

- 正常：补给→铁箱→补给→木箱；4行动达到13金币，剩1行动即胜利。
- 失败：补给5次，金币0，行动0；进入失败，再由玩家选择重试或返回标题。
- 边界：补给→补给→金箱→补给→木箱；第5行动达到16金币，必须先进入胜利，不得先判行动0失败。
- 无效请求：钥匙不足开箱返回规划，不消耗行动；不是免费领取该箱奖励。

图中的`init`对应ACT-START／ACT-RESTART，`valid`对应请求与资源条件，`result`对应RULE-COMMIT的玩家反馈，`goal`和`remaining`的先后对应RULE-END。绘图以看懂玩法为目标，图形闭合不证明难度、乐趣或玩家重试意愿。
