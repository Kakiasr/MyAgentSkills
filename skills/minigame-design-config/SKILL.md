# 小游戏内容设计与配置

## 项目入口与交付

在 minigame 项目根执行；先读根/目标目录最近 AGENTS、`Assets/Skills/README.md`，再按任务读取 `Assets/Game/Documentation/INDEX.md`、相关术语和功能文档。对象内容以 `Assets/Game/Configs/配置总表.xlsx` 为编辑源；历史备份、旧报告与旧字段不参与新内容生成。

共同状态和回退见 `Assets/Game/Documentation/Project/内容生产工作流.md`。已有资产覆盖与所有场景写入沿用 `Assets/Skills/project-work-order/SKILL.md`；候选在 Assets 外，清单由助手填写，用户无需维护 JSON。按需使用 `Tools/Content/README.md` 的清单及只读校验器。不能用“新建文件再改引用”绕过覆盖队列。

候选、正式落盘、Editor 验证和实际运行分别报告；只执行当前任务授权的检查。消费者文件存在与 hash 一致不证明运行接线。发送其他聊天前遵循已有通信授权，不由技能新增发送权限。

## 行为与数据

1. 以稳定对象 ID 对齐总表和实际定义。用户只填写现有列，其他属性由助手处理；不能通过改名创建第二身份。添加或删除对象时检查注册、投放、配方、存档与收藏引用。
2. 把效果拆成触发事件、条件、作用对象、行为顺序、数值运算、持续范围与重入规则；用于实现核对，不要求用户填写原子库。不确定目标/顺序/永久性时先问语义，其余独立工作继续。
3. 端口和定位只作设计评估，不新增运行属性；等级、占槽、同款判定和数值语义从当前术语与功能文档读取，不在技能维护第二份常数表。逐项核对代码入口，不能仅修改 `ConfigMasterReview.json` 宣称新效果已实现。
4. 按当前职责实现领域行为。常规 C# 用项目脚本技能；公共契约由框架集成。检查失败路径不消耗资源、事件不会重复结算、永久状态能保存恢复、双面与多槽实例身份正确；测试选择实际风险，不为纯文案写镜像测试。
5. 已确认新效果先回写总表候选，再同步内部配置。提供数值和效果分开；必要内联后解码必须逐字等于表内文本。用独立来源处理额外提供，不能把跳字表现当成数值实现。

## 配方与交付

修改配方先审查前置可达性、材料身份、同卡/同面条件、解锁是否消耗及槽位容纳；不得默认为消耗合成。只调整任务范围内内容，效果强度或路线存在实质歧义时给具体选择。

执行 `python3 Tools/Content/PrepareConfigMaster.py --output output/Implementation/<任务>`，成功后运行 `ValidateContentHandoff.py <输出>/Handoff.json`。失败说明需实现项，不从旧候选取文件覆盖。运行消费者、配方来源或表发生变化，重新审阅后生成。

给集成人：总表增量、实现路径、效果与数值绑定、候选清单、实际检查结果和用户验证入口。落盘后复读总表及配置，用 `--phase applied` 校验；未验证的触发情形明确列出。不要用旧配置兜底掩盖缺失定义。
