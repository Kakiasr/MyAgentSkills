# 文案与内联

## 项目入口与交付

在 minigame 项目根执行；先读根/目标目录最近 AGENTS、`Assets/Skills/README.md`，再按任务读取 `Assets/Game/Documentation/INDEX.md`、相关术语和功能文档。对象内容以 `Assets/Game/Configs/配置总表.xlsx` 为编辑源；历史备份、旧报告与旧字段不参与新内容生成。

共同状态和回退见 `Assets/Game/Documentation/Project/内容生产工作流.md`。已有资产覆盖与所有场景写入沿用 `Assets/Skills/project-work-order/SKILL.md`；候选在 Assets 外，清单由助手填写，用户无需维护 JSON。按需使用 `Tools/Content/README.md` 的清单及只读校验器。不能用“新建文件再改引用”绕过覆盖队列。

候选、正式落盘、Editor 验证和实际运行分别报告；只执行当前任务授权的检查。消费者文件存在与 hash 一致不证明运行接线。发送其他聊天前遵循已有通信授权，不由技能新增发送权限。

## 原文与含义

对象名称、提供数值、效果来自配置总表；UI 其他文案来自已确认功能文档或用户本次文本。引用当前术语决定，不能从旧版 tooltip 反推规则。用户要求保持原文时不增删标点、换词或润色；用户明确要求原子句式时才据确认语义整理，并先回写总表。

核对提供数值框和效果框的实际消费者。贴纸、卡牌与标签可能走不同视图，不因共享格式器存在就声称三者都显示正确。基础文案为空时不能凭旧字段补句；运行成长与基础原文的绑定按当前契约实现。

## 内联与翻译

1. 列出必须内联的符号/数值与当前格式器支持的标记，保留其他字符。只使用已实现标记；字面相同但语义不同的数字按对象和属性绑定，不能全局字符串替换。
2. 内联还原后逐字比较原文，包含空白、大小写和换行。模板显示与运行数值变化分别检查；正负号、乘号、指数、百分号不能混用。
3. 获得、额外提供、每次/本回合/永久、触发顺序都属于玩法含义；文案改动暗示新语义时交设计确认与实现，不默默通过文案修正代码行为。
4. 只有用户指定语言范围才翻译。保留对象 ID 与标记；译文另映射，不覆盖唯一中文源。文化表达或文字图像会改变外观时交主美；不要自动生成多语言艺术字替换已确认图。
5. 统计实际字符与字体覆盖，核对大小、换行、内容截断、数值框与效果框。静态字符串检查不证明 TMP 缺字或运行布局通过。

配置候选沿用 PrepareConfigMaster 与交付校验；效果变更仍先实现审阅。交付原文-内联映射、绑定参数、逐字比较结果、实际视图入口和未测布局。仅修文案无需新增玩法枚举、事件或原子库编辑界面。

## 项目显示入口

按当前代码定位卡牌的`CardTooltipQuery`、`CardTooltipContentComposer`和`CardTooltipView`，贴纸的查询/模板与`TooltipView`，以及标签待选/持有/收藏入口。卡牌数值框和效果框已有独立文案通路；需要验证两场景共享契约时核对CardGridV9与StickerGallery，不能用一个入口替代全部验收。只同步已实现内联标记，不重新启用归档别名或自动补正文。配置准备会校验玩法源码审阅状态；报错时交对应实现者核对，不为纯文案绕过版本检查。
